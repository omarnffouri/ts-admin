# ts_admin

Flutter admin app for a transportation / logistics system. Staff use it to run
day-to-day operations: chat and calling, clock in/out, HR and leave, vehicle and
driver inspections, shipments, invoices, the parts shop, file storage, and user
management.

Companion app to the driver app (`ts_driver`) against the same backend.

- **Flutter** 3.41.x · **Dart SDK** `>=3.0.0 <4.0.0`
- **Android** `com.transport_system.ts_admin` (minSdk 26, targetSdk 36)
- Version lives in `pubspec.yaml` as `X.Y.Z+build`

## Getting started

```bash
flutter pub get
flutter run                  # attached device; VSCode launch config is "ts_admin"
```

The app talks to `https://<host>/api/v2/`. Hosts are defined in
`lib/app/core/network/connection/environments.dart` (`dev` / `staging` /
`production`), and the active one is **hardcoded** in `api_constants.dart`:

```dart
static const Environment _env = Environment.dev;
```

There are no build flavors — switch environments by editing `_env`.

Firebase config is generated (`firebase_options.dart`); release builds are signed
via `android/key.properties`.


Test coverage is minimal — a few widget-layout smoke tests plus one storage
helper test. The suite is green (256 cases across 4 files), so a failure is
yours. `test/realtime_configuration_storage_helper_test.dart` used to fail on
Windows and no longer does — see `CLAUDE.md` before "fixing" the teardown it
deliberately omits.

Assets are generated by `flutter_gen` — never hand-edit
`lib/app/core/gen/assets.gen.dart`; add the file and re-run `build_runner`.

## Architecture

Clean Architecture per feature, with two dependency-injection systems that serve
different layers:

- **GetIt** (`sl`, wired in `lib/app/services/injection_service.dart`) — data and
  domain: repositories, data sources, use cases.
- **GetX** (`Get.put`, `Bindings`) — presentation: controllers, reactive state
  (`.obs` / `Obx`), and routing.

Each feature under `lib/app/modules/<module>/`:

```text
data/          models, datasources (call DioClient), repository implementations
domain/        entities, repository interfaces, use cases (one per operation)
presentation/  <screen>/{bindings,controllers,views}
```

Request flow:

```text
View → Controller (GetX) → UseCase → Repository → RemoteDataSource → DioClient
```

### Two things that surprise everyone

**`Either` is inverted.** This codebase uses `dartz` `Either<Type, Failure>` with
**Left = success, Right = failure** — the opposite of the usual convention:

```dart
response.fold(
  (data)    { /* SUCCESS */ },
  (failure) { /* FAILURE — failure.message */ },
);
```

**GetX wiring crosses modules without imports.** A controller registered with
`Get.put` in one module is reachable anywhere via `Get.find`, with no import
between the two files. Searching for imports will not tell you whether something
is used — grep the class name as well.

### Layout

```text
lib/
  main.dart                    runZonedGuarded → local db → DI → Firebase → runApp
  app/
    controllers/               app-wide GetX controllers (auth, call events, location)
    core/                      network, widgets, helpers, themes, utils, enums, values
    modules/                   one folder per feature (see below)
    routes/                    app_pages.dart (GetPage list) + app_routes.dart
    services/                  injection_service.dart, firebase_options.dart
```

Modules: `annoucments`, `assets_management`, `auth`, `chat`, `chat_detail`,
`clock-in-out`, `forms`, `forward_message`, `hr`, `inspection_management`,
`invoices_management`, `leave_management`, `main_screen`,
`media_picker_previewer`, `menu_page`, `request_loads`, `shipment`,
`shop_management`, `splash`, `storage`, `task_management`, `update_profile`,
`user_management`.

`main_screen` hosts the bottom navigation and mounts the clock-in/out, tasks,
safety, chat, shipments and menu tabs — the last two gated on role. Tab views are
mounted as widgets rather than navigated to by route name, so a registered route
is not proof that a screen is reachable that way.

### Storage and realtime

- **GetStorage** — app/user/settings key-value prefs
- **sqflite** — chat persistence (messages, conversations, group conversations)
- **flutter_secure_storage** — sensitive values
- **Pusher** (`dart_pusher_channels`) — chat sockets
- **Firebase** — FCM, Auth, Crashlytics, Realtime Database

### Vendored packages

`pro_image_editor/` is a local path dependency modified in-tree — edit it
directly and don't expect upstream parity. `flutter_callkit_incoming/` holds
native calling code.
